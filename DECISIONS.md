# Decisions

- 2026-10-31 Deliverable is a website (gallery walk), not a Claude Doc. The Cullionboy Claude Doc is kept for now.
- 2026-10-31 Host on GitHub (Pages from /docs) for simplicity. Cloudflare later, perhaps.
- 2026-10-31 Public is fine. No living people. 100/75/50 rule, not a calendar cutoff.
- 2026-10-31 Scope is Donegal only. Template may later be cloned for other counties.
- 2026-10-31 Clogher is the second townland, then Drumholm and Drumhome townlands.
- Dimon is treated as Dunnion as a working hypothesis (Cullionboy).
- Griffith's map is not part of the standard townland process (no high resolution images online).
- Tithe Applotment Books to be added as a source when available (sits before Griffith's).
- 2026-10-31 Two repos: GRA (research engine) and this one (publishing layer). One-way export contract (docs/EXPORT_CONTRACT.md, since superseded and removed, see the 2026-11-01 entries). Local 1926 census copy kept as source because GRA's lacks about 500 researcher-filled relationship values.
- 2026-10-31 Engine holds no townland content. Each townland carries `townland.json`, `content.json` and `records/corrections.json`; `tools/extract_census.py <name>` and `tools/build.py <name>` are parameterised. Cullionboy was moved over and its rebuilt page checked as identical in rendered text, tables and interactions (23 of 23 plates). The 1926 Bradley form 0016 to 0017 household fix is now an explicit, reasoned correction rather than code.
- 2026-10-31 The shared assistant protocol copies in the two repos no longer have to be byte-identical. The shared core (sections 1 to 8 and 10) should stay consistent in substance, each repo may add supplementary wording, and core changes are carried across in a follow-up PR.
- 2026-10-31 Clogher is built from the earlier Clogher study. Map material is left out. Griffith's land and buildings columns stay blank until the page image is re-read. Family plates count household members, not everyone with the surname.
- 2026-10-31 GRA and Donegal Townlands have distinct responsibilities. GRA supplies ingested source records and owns the source catalogue, ingestion definitions and URL patterns. Donegal Townlands uses those capabilities but does not depend on GRA's person-centred probabilistic matching engine. The source record is the unit of exchange; relationships between records and people, households or families are primarily established through human research and review in Townlands. GRA's specified source architecture may cover sources whose ingestion is not yet implemented, so specified, implemented and ingested capability must be distinguished.
- 2026-11-01 Donegal Townlands is independent of GRA. GRA's pipelines are person-stitching centric, which conflicts with the townland-centred goals here. Townlands owns its data, identifiers, source acquisition and processing, and may acquire and process sources directly. There is no export contract (docs/EXPORT_CONTRACT.md was superseded and has been removed; it survives in git history) and no required data flow. Elements of GRA's design may be reused case by case, for example its source catalogue, provenance architecture and ETL for particular source data files. This supersedes the 2026-10-31 export-contract and downstream framing above.
- 2026-11-01 Data architecture agreed in principle, recorded in docs/DATA_ARCHITECTURE.md (draft). Four layers (source, processing, research, presentation). Source observations, place associations, established research entities and assertions are kept distinct. Observation IDs are deterministic (source, locator, row). UUIDs are for established research entities only, recorded in one append-only registry. One master GEDCOM for the whole project, no townland-specific GEDCOMs. Separate property and land model. Identity and association decisions are by human review.
- 2026-11-01 A place gazetteer with stable place IDs is the first piece to settle (docs/GAZETTEER_SPEC.md, draft). The 1926 Clogher matching test found Keadew Lower missing from the townland dictionary. Matching runs on the original townland value, never on townland_clean, which folds Keadew Lower into Keadew Upper.
- 2026-11-01 Implementation approach (docs/REQUIREMENTS.md and docs/WORK_PACKAGES.md, drafts). The build pipeline is Python and the browser only displays static JSON produced by the build. Processed layers are CSV and JSON in git, with one generated master GEDCOM for people and relationships. Accept and reject decisions are made in a review CSV applied by script. Code from GRA is copied and adapted with a provenance header, not imported. GRA's person-linking pipelines are not reused.
- 2026-11-01 GRA's source ingest and its already fetched census files are the starting point for the source layer. The 15 census files in GRA data/ (Clogher including Magheraclogher, Donegal, Laghy, Tawnawully and Tullynaught, for 1901, 1911 and 1926; first committed to GRA on 2026-07-10) are adopted unchanged with a manifest entry that says the original download time is unknown. A DED search returns more than one DED (Clogher also returned Magheraclogher), so source files keep the complete response and selection happens in processing.
- 2026-11-01 (superseded by the next entry, kept for history) Proposed: the gazetteer is seeded from Logainm using a fetcher adapted from GRA, with the Logainm ID held as an external reference and a project UUID as the place identifier. The townland dictionary becomes a cross-check. This replaces the earlier plan to seed from the dictionary and townlands.ie, because the dictionary does not cover the other DEDs (all 51 Laghy townland strings differ from it) or town parts. Needs a Logainm API key.
- 2026-11-01 Proposed: researcher-filled values (for example the 519 relationship values in the local 1926 Clogher file) move to overlay files keyed by locator, each with a reason, so source files stay unchanged. The local 1901 and 1911 townland_clean columns fold Keadew Lower into Keadew Upper, which GRA's raw files do not, so matching always uses the original townland value.
- 2026-11-01 Open items: whether the public repository may hold processed research layers and the GEDCOM (recommendation: keep the full research layer private and commit only filtered output), whether the GEDCOM is ever edited in genealogy software, which genealogy software is used, and a Logainm API key.
- 2026-11-01 Logainm is the place authority and the Logainm ID is the place key. The project does not build a full gazetteer. GRA reached the same conclusion for its place authority. The project keeps a dated snapshot of Logainm responses in the source layer, a derived flat place table, name variants (census spelling to place key, accepted by human review), manual places for what Logainm lacks (town parts, church parishes, possibly Keadew Lower) with `dt-place:<uuid>` keys in the identifier registry, and associations. The own-UUID place IDs, hierarchy tables and time validity in the earlier gazetteer drafts are dropped. Logainm API key, licence and coverage are open. docs/GAZETTEER_SPEC.md is now draft 4 and describes this place layer.
- 2026-11-01 docs/EXPORT_CONTRACT.md was deleted from the repository (Mike, commit cb6a2d4) after being marked superseded. Guidance files no longer describe it as kept.
- 2026-11-02 Every Logainm-recognised townland in `places.csv` is eligible for an independently identifiable research case, whether or not historical records are available. The case is keyed by Logainm ID and can begin empty. Historical evidence enriches it incrementally. Case generation must be repeatable, preserve existing research and must not silently delete cases when a townland is absent from a later snapshot. Manual places remain a separate process.
- 2026-11-02 Wherever possible, published evidence should link directly to the original historical record or source image, not merely to a transcription or derived dataset, so readers can inspect the underlying evidence and draw their own conclusions.
- 2026-11-02 Every recognised place publishes what it has, then is enriched. A case with no records gets a place page at docs/<name>/ and a full study replaces it at the same URL. docs/index.html is always generated by tools/build.py (every build regenerates it), never edited by hand, and is the way to reach every page.
- 2026-11-02 Census returns are attached to townland cases for the Clogher DED only until the pipeline is proven. A census townland string attaches to a Logainm townland only on an identical name (ignoring case, accents and spacing), and is recorded as a proposed match, never confirmed. Every other spelling is listed in data/processed/places/census_spelling_review.csv for Mike to accept or reject, and his decisions are never overwritten. Cases with census returns publish them on their place page until a full study replaces it. Census persons born less than 100 years ago are withheld. The Tawnawilly DED follows once the Clogher pipeline is right.
- 2026-11-02 Mike accepted the 18 census spelling variants for the Clogher DED (1901 and 1926) listed in data/processed/places/census_spelling_review.csv. Basis: within each census year the unmatched spellings pair one-to-one with the places that have no other return that year, and townlands.ie confirms the canonical names. townlands.ie lists no variants, so it does not confirm the spellings themselves. Meenabrock has no census return in any year. Carnbeagh South has none in 1926 (the 1926 return is Carnbeigh North only), which is held open. Accepted spellings are shown on place pages as accepted on review.
- 2026-11-02 Privacy rule narrowed. A record taken unchanged from a source published by its custodian, such as the National Archives census releases (1926 and earlier), has already passed that custodian's privacy review, and the project does not withhold it again. The 100/75/50 rule continues to apply to information the project holds that is not from a published source (family knowledge, oral accounts, unpublished records, GEDCOM entries, photographs). The validator still refuses census files after 1926. PRV-01 and the Living people section of CLAUDE.md are updated to match. PRV-02 is unchanged.
- 2026-11-02 Mike's reading: a townland with no census return in a year almost certainly had no residents then, since these are rural and often mountain. So Meenabrock (no return in any year) and Carnbeagh South in 1926 are treated as no people, not as missing data. This is his judgement, held as a working reading, not a finding the pages assert.
- 2026-11-02 Logainm is the authority for which townlands exist. townlands.ie is a community resource, mostly correct, and is used as a cross-check only. O'Donnells Island exists but is not used administratively, so it has no Logainm townland and no case. If it is ever wanted it would be a manual place, separate from case generation.
- 2026-11-02 The purpose of the site is an immersive alternative to the dry browsing of record sites, so every place gets the gallery walk, not a plain page. The engine shows a plate only when its content exists. A townland with only a place record gets a short walk (title, not yet hung, what is still open, method and sources). Census returns add the households plate and records tables, and an authored study adds Griffith's, families and its own copy. Authored content always overrides generated content. Nothing is invented: generated text states only what the case holds.
- 2026-11-02 Logainm is shown as a source as well as the place authority. Every title plate carries the Logainm record link, the location and the CC BY 4.0 credit (PLC-08), including Clogher and Cullionboy. Parish and barony names come from data/processed/places/place_names.csv, which holds only what the Clogher and Cullionboy title plates already state (Donegal civil parish, Tirhugh barony) and the county, until the Logainm hierarchy is fetched. Irish names appear where places.csv has one (15 of 55).
- 2026-11-02 Clogher and Cullionboy are no longer handled as exceptions. They use the same census path (attach_census.py with records/corrections.json, which reproduces their hand-extracted census files exactly) and the same build path. extract_census.py is superseded and kept for reference. Their authored content.json remains the enrichment layer.
- 2026-11-02 Correction: earlier place pages described census rows as "as transcribed, with no interpretation added". The census files contain researcher-filled values in columns marked updated (for example relationships in 1926 and language in 1901), so that overstated it. The pages now say that some values were filled in or corrected by the researcher. Showing the original value beside the researcher's value remains open under EVD-02.
- 2026-11-02 A townland checked against the Clogher DED census files with no return records that fact in records/census_match.json (status checked), so a page can say "no return found" instead of "not yet attached". engine/place.html, the plain data-first place template, is no longer used by the build but is kept on purpose. Mike found it a useful researching aid and may use it later for a researcher view, so it must not be deleted.

- 2026-11-03 Census records tables link each row to the National Archives image of the original return ("Original"). URL patterns are copied from GRA docs/repositories.md v1.6 (Sources 3 to 5), URLs only and no data, and live in CENSUS_URLS in tools/build.py. 1901 and 1911 use the first image id of the household; 1926 uses the aform_name. A link appears only for years the case holds. The links have not been opened from the build environment, because network access from the shell is restricted. Mike to spot-check one return per year.
- 2026-11-03 Correction to the census links: they were first placed in a last column of the records table at the foot of the page, which is off-screen on a phone, and the family tables had none. The house or form number is now the link (marked with an arrow) in both the family evidence tables and the records tables, so it is always visible.
- 2026-11-03 Media feature specified in docs/MEDIA_SPEC.md (draft, branch feature/media). Header images (1 to 3 per townland) hang on top of the painted title scene. Household photos attach to the family plate by family name and show only on a new Photos tab, first and default, over the painted landscape with no cottages. The 1850s and census tabs are unchanged. Photos are shown whole in a light frame and never cropped.
- 2026-11-03 Images are committed as supplied and not resized (supersedes the earlier rule of about 1600 px web copies kept outside the repo; typical scans are a few hundred KB). Each townland has media/media.csv. Required: file, scope, caption, source. Optional: date, reference, people_shown, alt, link. An optional townlands/media_config.json base_url allows a CDN later with no CSV edits. CDN provider not chosen.
- 2026-11-03 Mike checks each photograph for privacy himself before adding it. The validator applies no 100/75/50 test to media and does not check people_shown. Where people_shown is filled it names only people already in the project datasets. This is Mike's decision and other assistants should not add an automated check or flag photographs on date grounds.
- 2026-11-03 Header photographs (MP4) are on the title plate. A photograph is shown whole in a frame sized from its own shape, never cropped. One wider than the screen is scaled down inside its frame. The title plate stacks title, photographs and hint in page order only when it has photographs, so the photographs cannot overlap the townland name on a short screen. Built pages in docs/ pick this up when all pages are rebuilt (MP7).
- 2026-11-03 Header photographs should be landscape. A portrait or square header gives a warning and still builds. Household photographs can be any shape. The header frame takes its height from the picture so the mat is even on a phone.
- 2026-11-03 Source for all of Mike's photographs in media.csv is "Personal photo". The first two, for Cullionboy: header panorama captioned Cullionboy, and a family photograph on The Kellys plate captioned Bella, Rose & Mary Kate Kelly. The census spellings Mary Katie and Rose Anne (1926, form 0002) differ from the caption and are noted in the Cullionboy STATUS.md, not changed.
- 2026-11-03 Family Photos tab (MP5) built. A family with photographs gets a first, default Photos tab showing the midday landscape with no cottages and the photographs whole in frames in a single row that scrolls sideways when needed (a change from the wrapping arrangement first sketched). The year tabs are unchanged and a family with no photographs looks as before. Cullionboy is the pilot.
- 2026-11-03 MP7: all pages rebuilt with the media-aware engine in a separate commit. For the 54 pages without media the embedded data is identical and the rendered text, plates and tabs match before and after at 390 and 1440 px. The media feature is complete on branch feature/media except the optional CDN route (MP8), awaiting review.
